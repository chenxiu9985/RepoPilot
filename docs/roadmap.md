# 项目路线图

各 Phase 对应 GitHub Milestone。验收行为决定完成情况，时间估计在每周回顾时调整。

| 阶段 | 交付与验收 |
| --- | --- |
| Phase 0 | 可安装项目、CLI 帮助、配置、测试、CI、架构文档与协作模板 |
| Phase 1 | 本地 Python 仓库 → 真实模型调用工具 → 独立工作区补丁 → Docker pytest → Diff 与执行报告 |
| Phase 2 | FastAPI、SQLite、历史任务、状态与执行轨迹查询 |
| Phase 3 | 恢复、审批、上下文管理与按需增加的简单界面 |
| Phase 4 | 20～30 个可复现任务、实际实验统计、部署和演示资料 |

## Phase 1 的近期任务

1. 定义 TaskState 和允许的状态转换，覆盖终态及非法转换。
2. 定义模型消息 / 调用接口与可脚本化 Fake，无需 API Key。
3. 实现工具注册、schema 校验和统一错误结果。
4. 实现有限步骤 Agent Loop，覆盖工具反馈、正常结束和预算终止。
5. 创建独立工作区，实现 list_files、read_file、search_code 及边界验证。
6. 实现 apply_patch 和 get_diff，验证无效补丁与原始仓库不变。
7. 实现受限 Docker pytest 执行器与明确标记的 Mock。
8. 接入兼容 API、超时、有限重试与可获得的用量统计。
9. 完成 CLI run、执行轨迹、Diff 与测试报告。
10. 建立小型 Python 示例：先证明缺陷，再运行修复，再独立验证目标行为。

前四项先形成 Fake 驱动的最小流程；最后一项以实际模型和 Docker 执行为验收依据。
若真实依赖暂时不可用，记录阻塞项，不能把 Mock 演示标成 Phase 1 完成。

## 每周回顾

- 演示一个已经通过验收的行为。
- 记录实际遇到的问题与关键设计取舍。
- 检查任务是否过大，调整下一周优先级。
- 后续想法进入待考虑列表，不自动扩大当前任务范围。
